# oc-recall

> Поиск по прошлым сессиям OpenCode по смыслу, а не по заголовку. Локально, офлайн,
> без моделей по умолчанию.

OpenCode хранит все сессии в локальном SQLite и умеет фильтровать их только по заголовку.
Заголовок — это три слова, и нужных слов в нём обычно нет. Поэтому на вопрос «где мы
подбирали билет с пересадкой в Лиссабон» встроенный выбор сессий молчит, хотя разговор
лежит рядом.

`oc-recall` индексирует сам текст переписки и отвечает на такой запрос меньше чем за
секунду: офлайн, без ключей и без модели.

```
1. [2.41] 2026-11-14 — Билеты в Лиссабон
   ~/src/travel
   ses_04f1c9d2ffe...  (релевантность 100%, фрагментов 4, вопрос)
   …самый дешёвый билет в Лиссабон — с одной пересадкой в Стамбуле, на треть …
```

## Что умеет

- **Склеивает формы слов.** Снимает русские окончания, разбирает дефисы и склеивает
  остальное через пятибуквенную основу, поэтому `путешествие` находит `путешествовать`.
- **Двуязычный.** Встроенный словарь связывает английские и русские термины:
  `flight` ↔ `рейс` ↔ `авиабилет`, `layover` ↔ `пересадка`, `budget` ↔ `бюджет`.
- **Взвешивает по редкости.** Редкое слово весит больше частого, поэтому выдачу
  определяет тема, а не длина сессии.
- **Гасит слова-намерения.** «обсуждение», «найти», «разбор» весят четверть от слова
  темы, иначе выигрывают сессии, где просто много текста.
- **Инкрементальный индекс.** Новые и изменённые сообщения переиндексируются, удалённые
  вычищаются. Полная пересборка 7,5 тыс. кусков — около 7 с, досборка — меньше секунды.
- **Одна команда.** Пять результатов по умолчанию, `--json` для скриптов.

## Установка

```sh
git clone https://github.com/<owner>/oc-recall.git ~/.config/opencode/skills/oc-recall
cd ~/.config/opencode/skills/oc-recall
./install.sh
```

Установщик ставит скилл симлинком, создаёт команду `oc-recall` в `~/.local/bin`
и запускает `--setup`: собирает индекс и ставит почасовое обновление (launchd на macOS,
systemd-таймер на Linux, готовая строка cron в остальных случаях).

Требования: Python 3.9+, только стандартная библиотека. Сеть не используется.

Вручную, если нужно:

```sh
python3 scripts/oc_recall.py --setup        # папки + словарь + индекс + обновление
python3 scripts/oc_recall.py --no-agent     # или без обновления
```

## Быстрый старт

```sh
oc-recall "билет с пересадкой в лиссабон"
oc-recall -n 10 --json "разбор бюджета по категориям"
oc-recall -d ~/src/travel --days 30 "отель с бесплатной отменой"
oc-recall --open "рефакторинг api"
```

## Команды

| Команда | Что делает |
|---|---|
| `oc-recall "..."` | поиск, 5 результатов |
| `-n, --limit N` | сколько результатов |
| `--json` | вывод в JSON |
| `-d, --dir ТЕКСТ` | только сессии, в пути которых есть ТЕКСТ |
| `--days N` | только за последние N дней |
| `--explain` | показать, как запрос разобран на понятия |
| `--open` | открыть лучшую сессию в OpenCode |
| `--setup` | первичная настройка |
| `--status` | состояние индекса и обновления |
| `--sync` | досборка индекса |
| `--reindex` | полная пересборка |
| `--install-agent` / `--uninstall-agent` | управление обновлением |

Коды выхода: `0` — есть результаты, `1` — ничего не найдено, `2` — ошибка вызова,
`3` — проблема окружения (нет базы OpenCode, пустой индекс).

## Настройка

| Что | По умолчанию | Переопределение |
|---|---|---|
| Файл индекса | `~/.local/share/oc-recall/index.db` | `OC_RECALL_INDEX` |
| Личный словарь | `~/.config/oc-recall/synonyms.json` | `OC_RECALL_DICT` |
| База OpenCode | `~/.local/share/opencode/opencode.db` | `OPENCODE_DB` |
| Порог автообновления | 300 с | `OC_RECALL_AUTO_SYNC` |
| Смысловой режим | выключен | `OC_RECALL_EMBED_MODEL` |
| Адрес Ollama | `http://127.0.0.1:11434` | `OC_RECALL_OLLAMA` |

### Необязательный смысловой режим

Совпадение слов слепо к перефразу без общих слов. Мультиязычная модель эмбеддингов
закрывает часть этого разрыва:

```sh
OC_RECALL_EMBED_MODEL=bge-m3 oc-recall --reindex
```

Модель должна быть установлена в Ollama. Индексация — около 15 минут на 7,7 тыс. кусков
однократно, дальше около секунды на обновление; индекс вырастает примерно на 30 МБ.
Найденное только по смыслу помечается флагом `semantic`.

Замер на 104 реальных сессиях: с `bge-m3` гибрид сохраняет все лексические попадания
(8 из 8) и разделяет шум и реальное совпадение (шум ≤ 0.52, совпадение 0.82). Но
перефразы без общих слов, написанные руками, он **не** нашёл: сессия смешивает темы, и
один вектор на сессию размывает сигнал. Это фундамент, а не обещание полного смыслового
поиска. Цифры и подробности — в `references/design.md`.

Личный словарь дополняет встроенный набор своими названиями машин, продуктов и жаргоном
проекта:

```json
{
  "groups": [
    ["projectx", "px"],
    ["acme", "acme-corp"]
  ]
}
```

Создаётся пустым при первой настройке с правами `600` и никогда не покидает машину.

## Ограничения

- **По умолчанию поиск лексический.** Полный перефраз без общих слов («денег в этом
  месяце в обрез» против сессии «разбор бюджета») не найдётся, если слова не совпадут и
  их не свяжет словарь синонимов. Замеры и необязательный режим с эмбеддингами —
  в `references/design.md`.
- **Только OpenCode.** Индексатор читает схему базы OpenCode; для других инструментов
  нужен свой адаптер.
- **Русский стемминг — эвристика.** Одиннадцать групп окончаний покрывают частые случаи;
  редкие формы могут не совпасть, для этого есть словарь синонимов.
- **Встроенный выбор сессий не заменяется.** Это отдельный CLI и инструкция для агента;
  чтобы заменить пикер в TUI, нужен пропатченный бинарник.
- **Запросы из одних чисел** почти не находят: в цифрах нет темы.
